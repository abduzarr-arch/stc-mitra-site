# НТЦ Митра

Корпоративный сайт НТЦ Митра и два серверных ИИ-инструмента для ГИПов, РП, технических заказчиков и служб строительного контроля:

- нормативно-организационный помощник;
- помощник по предварительному визуальному осмотру конструкций.

## Запуск

```bash
npm start
```

По умолчанию сервер работает на порту `8080`. На Amvera используется Node.js 20 и команда `npm start`.

## Контур ИИ-помощника

Endpoint: `POST /api/normative-assistant`.

1. Черновой агент формирует восемь разделов нормативно-организационного ответа.
2. Верификатор проверяет формулировки и ссылки.
3. При наличии совместимой модели OpenAI верификатор использует Responses API и обязательный веб-поиск по ограниченному перечню нормативных источников.
4. Если поиск недоступен, система переходит в режим проверки моделью и явно сообщает пользователю о необходимости ручной сверки.
5. Ответы и уточнения сохраняются в закрытом журнале при явном согласии пользователя.

ИИ-помощник не выполняет инженерные расчеты, не назначает усиление и не заменяет юридическую или инженерную экспертизу.

## Контур визуального осмотра

Endpoint: `POST /api/visual-inspection`.

1. Пользователь загружает до пяти фотографий и дает отдельное пояснение к каждому снимку.
2. Изображения уменьшаются в браузере и пересобираются без исходных EXIF-метаданных.
3. Два мультимодальных агента независимо анализируют наблюдаемые признаки.
4. Третий контур сопоставляет выводы, удаляет неподтвержденные утверждения и проверяет нормативные основания через веб-поиск.
5. В журнал записываются только текстовые пояснения и итоговый отчет. Сами изображения не сохраняются.

Визуальный помощник не определяет по фотографии прочность, несущую способность, категорию технического состояния или безопасность конструкции.

## Переменные окружения

Обязателен хотя бы один ключ для чернового агента:

- `DEEPSEEK_API_KEY`
- `OPENAI_API_KEY`

Основные настройки:

- `DEEPSEEK_BASE_URL` — по умолчанию `https://api.deepseek.com`
- `DEEPSEEK_MODEL` — модель чернового агента
- `OPENAI_BASE_URL` — по умолчанию `https://api.openai.com/v1`
- `OPENAI_DRAFT_MODEL` — OpenAI-модель чернового агента, если DeepSeek не задан
- `OPENAI_VERIFIER_MODEL` — модель верификатора; для веб-проверки она должна поддерживать Responses API и инструмент `web_search`
- `OPENAI_VISION_MODEL` — основной мультимодальный обследователь
- `OPENAI_VISION_REVIEW_MODEL` — независимый мультимодальный проверяющий
- `OPENAI_VISION_NORM_MODEL` — синтезатор отчета и проверяющий нормативных оснований
- `OPENAI_WEB_VERIFY=false` — явно отключить веб-проверку
- `SAFETY_IDENTIFIER_SALT` — случайная строка для формирования обезличенного стабильного идентификатора запросов

Защита и эксплуатация:

- `ASSISTANT_TIMEOUT_MS` — таймаут одного обращения к провайдеру, по умолчанию 75000 мс
- `ASSISTANT_RATE_WINDOW_MS` — окно ограничения запросов, по умолчанию 15 минут
- `ASSISTANT_RATE_LIMIT` — максимум запросов с одного адреса за окно, по умолчанию 8
- `ASSISTANT_MAX_CONCURRENT` — максимум одновременно обрабатываемых запросов, по умолчанию 4
- `ADMIN_LOG_USER` — имя пользователя закрытого журнала, по умолчанию `admin`
- `ADMIN_LOG_TOKEN` — длинный случайный пароль закрытого журнала
- `DIALOG_LOG_PATH` — по умолчанию `/data/assistant-dialogs.jsonl`

Ключи и пароли добавляются только в переменные окружения Amvera и не коммитятся в Git.

## Журнал диалогов

- просмотр: `/admin/dialogs`
- CSV: `/admin/dialogs.csv`
- срок хранения: 90 дней
- IP-адреса не записываются в журнал
- записи связываются по `conversation_id`

## Основные файлы

- `server.js` — HTTP-сервер, API, защита и оркестрация агентов
- `assets/assistant.js` — интерфейс, форматирование ответа и уточнения
- `assets/visual-inspection.js` — подготовка фотографий и интерфейс визуального осмотра
- `dialog-log.js` — хранение и закрытая панель диалогов
- `prompts/agent1_normative_consultant.md` — правила чернового агента
- `prompts/agent2_reference_verifier.md` — правила проверяющего агента
- `ai-normative-assistant.html` — страница помощника
- `ai-visual-inspection.html` — страница визуального осмотра
